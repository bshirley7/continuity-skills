# Hierarchy

## Generalized principles

- Preserve nested orientation from account or workspace through area, page, object, and transient substate, with the selected scope visible near the content it governs.
- Reserve the strongest emphasis for the current state, unresolved consequence, or next meaningful action rather than greetings, tutorials, upgrades, or generic recommendations.
- Separate orientation, state, evidence, decision, and secondary exploration through stable regions, spacing, type, order, and contrast instead of relying on one signal alone.
- Use drawers, sheets, menus, and contextual panels for focused secondary tasks only when the originating object, selected scope, and escape path remain legible.
- Group controls by task and consequence, place the primary action near the object or scope it changes, and separate destructive or system-level actions from routine editing.
- For data and status regions, pair each emphasized value with scope or freshness and then reveal supporting trend, evidence, or decision context before secondary detail.
- Treat empty and zero states as real application states: explain what is absent, preserve surrounding orientation, and offer a proportionate next action without outranking existing work.
- Use consistent form for comparable items and vary size, color, position, or persistence only when the semantic priority or consequence is genuinely different.
- When several important actions coexist, establish one state-dependent primary action and route the remaining actions as alternatives, tools, or later steps.

## Variation levers

- Use persistent side navigation and a fixed scope header on wide application layouts, and compress orientation into a title, selected destination, and recoverable navigation layer on narrow screens.
- Use a table or list when comparison and repetition dominate, a detail layer when inspection is temporary, and a dedicated page when the secondary task changes the user's working context.
- Lead dashboards with an anomaly or decision when action is required, and with a concise state summary when monitoring is the primary task.
- Keep editor canvases visually dominant while using side regions for structure and tools; collapse tools contextually when space or task focus requires it.
- Use banners only for time-sensitive system consequences, inline callouts for task-local guidance, and dismissible help for optional learning.
- Show one creation action when the object type is known, or expose a labeled action family when users genuinely create several distinct object types.
- Use color to reinforce state or consequence after labels and grouping have established meaning, not as the sole hierarchy signal.

## Tensions and tradeoffs

- Persistent navigation improves orientation while reducing space for the active task.
- Large setup or upgrade callouts clarify account needs while displacing current application work.
- Uniform cards improve consistency while flattening meaningful differences in state and urgency.
- Multiple panes preserve context and tools while increasing simultaneous competition for attention.
- Dimming the origin strengthens a contextual layer while weakening the relationship to the underlying object.
- Whitespace creates focus while making sparse or empty states appear more important than their operational value.
- Keeping every action visible improves discoverability while obscuring the state-dependent primary action.
- Strong color accelerates scanning while risking false priority when it reflects branding rather than consequence.

## Failure modes

- The user cannot tell which account, workspace, area, object, or time range governs the visible content.
- A greeting, tutorial, upgrade, promotion, or recommendation receives more emphasis than current work or unresolved state.
- Comparable cards and controls use equal weight even when one represents an anomaly, required action, or destructive consequence.
- A drawer, modal, menu, or panel obscures the originating object or lacks a clear escape path.
- Primary, secondary, destructive, and system-level actions are mixed in one undifferentiated group.
- A metric is emphasized without scope, freshness, comparison basis, evidence, or a resulting decision.
- An empty state occupies dominant space without explaining why it is empty or what proportionate action is available.
- Several saturated actions compete while the interface leaves the state-dependent next step implicit.
- Color or iconography carries meaning that labels, grouping, and order do not support.

## Anti-patterns

- Using a collection of equal-sized cards as a substitute for deciding what matters now.
- Placing a persistent upgrade or onboarding banner above every operational task regardless of urgency.
- Showing global, local, object, and contextual controls with the same visual treatment.
- Opening a full-height secondary panel without preserving the selected row, document, or scope that invoked it.
- Combining navigation, editing, sharing, export, and destructive actions in one long overflow menu.
- Using green growth indicators, red warnings, or saturated buttons without a labeled semantic basis.
- Duplicating the same primary action in several regions without explaining whether they have different scope.
- Making empty-state illustration or help content more prominent than existing data or work.
- Hiding current state in a placeholder or disabled control without an explanatory label.

## Acceptance and review questions

- Can the user identify the active account or workspace, area, page, object, and temporary substate from the current view?
- Does the strongest emphasis correspond to current work, an unresolved consequence, or the next meaningful action?
- Are orientation, state, evidence, decision, and secondary exploration distinguishable without relying only on color or icons?
- When a secondary layer opens, are its origin, selected scope, and escape path still clear?
- Are controls grouped by task and consequence, with destructive and system-level actions separated from routine work?
- Does every emphasized metric or status state its scope or freshness and connect to evidence or a decision?
- Do empty and zero states explain what is absent and offer a proportionate next action without displacing real work?
- Are comparable items visually consistent, and can every visual exception be justified by semantic priority?
- If several actions are visible, can the user identify the state-dependent primary action and understand the alternatives?
