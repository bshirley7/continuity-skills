# Cognitive load and progressive learning

## Generalized principles

- Reduce extraneous load before simplifying the task itself: remove unrelated content, group information by the decision or action it supports, use familiar structure and language, and keep necessary instructions adjacent to the step where they apply.
- Externalize memory through visible current state, prior choices, completed and remaining steps, examples, defaults, saved work, and review surfaces; never require recall when the interface can provide recognition or continuity.
- Teach progressively through one meaningful outcome at a time, representative examples, guided practice in the real context, feedback tied to the attempt, and durable routes to revisit guidance; exposure to a tour is not evidence of learning.
- Adapt the amount and sequence of guidance to task complexity, consequence, prior knowledge, stress, and accessibility needs while preserving core information, user control, correction, and a path through the task without optional enhancement.

## Method

- Define the real task outcome, prerequisite knowledge, consequence, likely interruptions, and accessibility context.
- Separate intrinsic task complexity from avoidable interface, language, navigation, and memory burden.
- Map what users must perceive, understand, remember, decide, do, verify, and recover at each step.
- Move necessary information and examples to the point of use and externalize state that would otherwise require recall.
- Prototype first attempt, correction, interruption, resumption, and later independent use.
- Test task success, errors, time, comprehension, confidence, recall, transfer, recovery, and dependence on help with representative users.

## Ethical safeguards

- Do not remove material information in the name of reducing cognitive load.
- Do not use progress, rewards, or completion pressure as a substitute for learning or task value.
- Do not force education before unrelated work.
- Do not infer competence from tutorial completion.
- Do not make dismissal permanently remove access to help.
- Include cognitive disability, low literacy, stress, interruption, and constrained-device conditions in evaluation.

## Variation levers

- Use one topic per step for unfamiliar or consequential tasks and denser grouped workflows for practiced expert work.
- Use contextual instruction for the current action and a durable learning center for deeper self-directed study.
- Offer examples, demonstrations, or guided practice according to the type of knowledge and cost of error.

## Tensions and tradeoffs

- More steps reduce local complexity while increasing navigation and duration.
- Persistent guidance supports resumption while competing with the work surface.
- Automation reduces effort while hiding the model users need for later correction.

## Failure modes

- Information is hidden even though it changes the current decision.
- A progress indicator reports pages rather than meaningful task state.
- Help explains interface controls but not the user's outcome.
- Users succeed once with guidance but cannot repeat or transfer the task.

## Anti-patterns

- One tour fits all.
- Tooltip as curriculum.
- Progress without task state.
- Simplification by omission.
- Memory test disguised as workflow.
- Tutorial completion as competence.

## Acceptance and review questions

- Is necessary information available at the point of use without hiding material consequences?
- Which state or knowledge would otherwise have to be remembered?
- Does guidance teach a meaningful outcome through practice and feedback?
- Can users dismiss and later rediscover help?
- Can interrupted users resume without reconstructing context?
- Does evaluation measure later independent use and transfer rather than tutorial completion?
