# Utilitarian

## Generalized principles

- Organize the interface around the current object, scope, state, and next operation; use direct labels and stable regions before adding summaries or personality.
- Make dense tables operational through stable row identity, decision-relevant columns, exact values and units, visible filters and structure controls, and contextual actions bound to selection.
- Pair technical identifiers with plain-language meaning, group long control sets semantically, preserve current values, and expose one explicit save boundary.
- At destructive, automated, or costly boundaries, name the affected scope, consequence, run or save state, cost or resource use, history, cancel or stop, and recovery.
- On mobile, prioritize due work, resource status, recent outcomes, and the primary task while keeping navigation and creation reachable without oversized low-value cards.
- Keep assistance subordinate to inspectable work artifacts: users should be able to verify rows, fields, state, validations, calculations, and changes independently of conversational guidance.

## Variation levers

- Use tables for comparison and queues, cards for a few bounded mobile states, and forms for configuration.
- Use compact density for expert work and comfortable density for mixed audiences.
- Reveal bulk actions after selection while preserving count and identity.
- Use machine-readable identifiers when required, paired with plain-language descriptions.
- Use accent color for state and consequence rather than decoration.

## Tensions and tradeoffs

- Directness improves speed while becoming cryptic without explanation.
- Density supports comparison while increasing scan burden.
- Configurability supports experts while weakening defaults.
- Sparse mobile cards improve touch access while wasting space.
- Inline automation accelerates work while increasing cost and scope risk.

## Failure modes

- The current object or scope is ambiguous.
- Tables expose many columns without task relevance.
- Bulk actions lose selection count or identity.
- Permissions show identifiers without consequences.
- Save, run, cost, or destructive state is hidden.
- Mobile homes prioritize greetings or empty cards over due work.
- Conversational assistance becomes the only way to inspect or change an artifact.

## Anti-patterns

- Decoration around operational tables.
- Icon-only batch actions.
- Unlabeled machine scopes.
- Silent autosave for consequential settings.
- Destructive confirmation without affected scope.
- Dashboard cards with no decision value.
- Automation without cost or stop control.
- Chat-only artifact state.

## Acceptance and review questions

- Are current object, scope, state, and next operation explicit?
- Do tables preserve row identity, meaningful columns, exact values, filters, and selection-bound actions?
- Are technical identifiers explained and grouped with current values and save state?
- Do destructive, automated, and costly actions show consequence, state, cost, history, and recovery?
- Does mobile prioritize due work, resources, recent outcomes, and the primary task?
- Can users inspect artifacts and changes independently of assistance?
