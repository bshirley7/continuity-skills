# Continuity Design

Read [the learned playbook](references/learned-playbook.md) for evaluated usage-derived heuristics. It may refine routine technique but never overrides this skill, the Continuity contract, machine state, privacy boundaries, or human authority. After a meaningful evidence-backed outcome, route only a sanitized structured usage record through `$continuity-improve`; never copy raw transcript or tool payload content.

Default to a short adaptive live-research pass, announce it, and offer an opt-out. The agent may use web and image search to gather private evidence; the installed Continuity runtime remains network-free and only validates and hashes local records. Honor offline, declined-research, and user-supplied-only modes. Never access an external maintenance system from this skill.

Read [workflow handoffs](../../references/workflow-handoffs.md), [output quality rubrics](../../references/output-quality-rubrics.md), [decision lenses](../../references/decision-lenses.md), and the [Continuity contract](../../references/continuity-contract.md). Machine state and approval boundaries remain authoritative.

When evaluating whether this workflow materially improves design quality, use the blinded paired structure in [output-benchmark.example.json](references/output-benchmark.example.json). Deterministic scenarios prove contract behavior only; they are not aesthetic evidence.

Before merging a material change to this workflow, run the applicable versioned benchmark. Use the [Continuity homepage benchmark](references/continuity-homepage-benchmark.md) for web and UI direction changes and the [Continuity presentation benchmark](references/continuity-presentation-benchmark.md) for document, deck, sequence, or presentation changes. A cross-modality workflow change runs both. Each benchmark is a staged, human-gated acceptance run: directions can validate before selection, but a benchmark passes only after private prototype evidence, exact design approval, an outside human score of at least 75, and no hard failure. Keep run artifacts private. For repeated workflow refinement, bind each evaluation and self-assessment into the native [design improvement cycle](references/improvement-cycle.md). Use `fresh-design-experiments` when the objective is to learn across diverse outputs: every round must restart research, moodboarding, generative exploration, and concepts from a new creative seed rather than polishing the prior design. By the third round, require full design-system distance, unique interactions across at least three journey roles, and a review of avoided and recurring house tells. Use `artifact-refinement` only when the objective is to improve one chosen artifact. The cycle can resume checks and preserve findings but cannot accept its own output. A benchmark exercises the complete process; it does not replace blinded paired output evaluation or authorize implementation.

## Preconditions

1. Run `continuity project doctor` and confirm the `design` collection is enabled and healthy.
2. Retrieve relevant captures, trusted memory, PRDs, feature requests, product documentation, application structure, existing interface or artifact context, and any existing `docs/design/design.md`. Use that evidence to reconstruct the working title, intent, audiences, and target modalities; do not require the user to know or supply those fields.
3. Read [catalog.json](references/catalog.json). Treat industry, section, theme, message-structure, and lens labels as optional internal retrieval aids, not questions the user must answer or concepts the design must name. Read category references when the user explicitly supplies a matching concept or the project context makes a reference materially useful. Category packs refine their foundation; they do not replace it. Apply [lens-routing.json](references/lens-routing.json) privately as a review aid when lenses are not explicit. Record inferred checks and pack provenance in private machine state without requiring the design document to name them.
4. Treat existing favorable behavior and explicit non-regression requirements as constraints, not as disposable context.
5. Read [creative-director workflow](references/creative-director-workflow.md), [creative direction methodology](references/creative-direction-methodology.md), [the generative concept laboratory](references/generative-concept-laboratory.md), and [the native AI-slop gate](references/ai-slop-gate.md). For a slide deck, presentation document, keynote narrative, or browser-rendered deck, also read and apply [presentation design methodology](references/presentation-design-methodology.md). When a reference or generated study depends on subject occlusion, embedded type, layered material, or characteristic display typography, also read and apply [compositional asset and type fidelity](references/compositional-asset-and-type-fidelity.md). When creating, materially reshaping, or generating an artifact from a direction, also read [distinctive expression methodology](references/distinctive-expression-methodology.md). For a film-led, looping-hero, section-loop, scroll-driven, macro, spatial, or continuous-media web experience, also read [cinematic media storytelling](references/cinematic-scroll-experiences.md). Assess the existing design before proposing change; do not invent findings for surfaces or artifacts you did not inspect.
6. For React or React-based web work, inspect the actual implementation system before calling a direction implementation-facing: framework and versions, package manifest, styling and token systems, installed UI, motion, data, and icon libraries, reusable component roots, Storybook or preview harnesses, and local asset roots. Record this as evidence-bearing `implementation_context`; never infer installation from familiarity or add a dependency during design work.

## Direction workflow

Tell the user that one sentence is enough and that they may react to visuals rather than supply design terminology. Infer a collaboration profile and specialization from context. Ask one calibration question only when the profile remains materially unclear. Apply the profile as an interaction contract: give `guided` users a decisive plain-language recommendation and three-to-five numbered reactions; expose assumptions and system tradeoffs to `collaborative` users; use professional shorthand, direct creative challenge, and boundary studies with a `creative-peer`. Do not merely record the profile.

1. Prepare a private design input from [creative-director input](references/creative-director-input.example.json) and [design input](references/design-input.example.json), set `workflow_version: 3`, and supply agent-authored project-specific directions. Workflow v3 adds a mandatory reference-reconstruction and adaptation gate; v2 records remain readable. The runtime rejects recovery directions for creative-director workflows; an incomplete user brief is not permission for generic agent output. Use [distinctive-expression.example.json](references/distinctive-expression.example.json) as the direction-level shape when distinctive expression is in scope. Derive the working title, intent, audiences, and targets from the request and retrieved project evidence. Treat them as agent-authored working fields, not user intake requirements. Record inspected evidence, current strengths, gaps, design debt, uncertain assumptions, preservation requirements, non-goals, validation criteria, and unresolved material questions. For every material insight that changes the design, add an `insight_decisions` record connecting it to a concrete design response, affected surfaces and states, and observable evidence. Do not turn every observation into a UI element. Preserve the user's natural language. Do not ask the user to classify the work by industry, section, theme, message structure, lens, style taxonomy, or other design terminology. Use inferred categories privately when they materially improve retrieval and record their provenance; do not expose them as user requirements. Use `consequences`, `workflow_signals`, `interaction_signals`, and `risk_signals` internally when those conditions are evident.
2. Proceed with the strongest evidence available. Do not stop merely because the title, intent, audience, target, style, or desired approach is incomplete. Choose a provisional scope, make uncertainty visible, and produce useful directions. Ask concise questions alongside the result when an answer would materially improve the next revision; incorporate later answers through normal design revision.
   Extract every unresolved fact or question from supplied briefs, documents, and project context into `source_uncertainties`. Give each an explicit disposition of `open`, `assumed`, `resolved`, or `deferred`: open and deferred items must remain in `open_questions`; assumptions must remain verbatim in `working_assumptions`; resolved items require a response and source evidence. Never convert silence into resolution.
   Before authoring directions, record `modality_assessment` from ordinary-language evidence: observed output signals, selected targets, rationale, and any resolved conflicts. Distinguish UI, document, presentation, and image intent even when HTML is used as a review carrier. A browser-rendered notice or slide deck is not thereby a UI design. For presentation work, also record whether the artifact must work live, as read-ahead, or in both modes. Resolve a material modality conflict before direction authoring rather than letting implementation convenience select the target.
3. Before authoring directions, run the private [generative concept laboratory](references/generative-concept-laboratory.md). Derive four to eight project-specific exploration lenses, then declare a range plan spanning at least four art-direction families, three rendered typography strategies from three families, three composition families, four page grammars, three interaction or motion strategies, and five page-depth roles including opening, proof, closure, and a quiet or edge state. Create eight to twelve inexpensive seeds across at least three media when available, bind every seed to that range plan, cross-pollinate the strongest relationships, and shortlist three to six. For every promising generated art family, produce two to four style-frame alternatives, explicitly select and reject frames, and extract at least three system rules plus a first-party derived artifact. Use image generation and editing to discover alternate composition, material, imagery, type, motion, interaction, and deeper-page ideas—not only to illustrate an already chosen website or produce abstract tactile objects. Test typography with real rendered copy, source and license evidence, project-specific customization, and narrow behavior; at least one study must go beyond system-only fonts. Keep early experiments upstream of responsive HTML so the browser does not collapse every idea into the same familiar layout. Validate the record with `continuity design concept-lab-validate --input <laboratory.json>` and attach it as `generative_exploration`. Generated material is illustrative, never observed. When tools or network are unavailable, use SVG, type, motion-frame, collage, and code studies; if exploration is declined or deliberately omitted, record a fail-visible rationale.
   Before expanding shortlisted seeds into complete concept pages, run [precision reference translation](references/reference-translation-fidelity.md) using the [precision manifest example](references/reference-translation.example.json). Treat the moodboard as an extraction surface: name the exact crop, proportion, type placement, rhythm, material, interaction, or transition worth copying, plus its private copy action, project adaptation, and shipping transformation. Capture and rebuild each named source separately at wide and narrow viewports; never hide uncertainty inside a blended category reconstruction. Accurate copying is expected in the private learning stage. Complete two visual-difference correction passes, compile at least eight located and measured grammar constraints, build a literal Continuity substitution while freezing that grammar, then introduce only one to four recorded divergence dimensions. Preserve real or generated media when it carries the source's material behavior; generic circles, ribbons, particles, cards, gradients, and oversized marketing copy are not acceptable substitutes. For occluded type or layered material, generate registered background and alpha-bearing foreground assets, keep copy as live type between them, and verify actual prototype consumption. Match typographic character with a real licensed face or measured transformation; a category substitute or browser fallback is not sufficient. Apply [compositional asset and type fidelity](references/compositional-asset-and-type-fidelity.md). A reviewer distinct from the preparer must validate the combined source → reconstruction → literal substitution → adaptation pixels with `continuity design reference-validate --manifest <reference-translation.json>`. Each candidate concept must later bind exactly one validated adaptation. Originality and shipping-distance requirements apply after the literal baseline, not before it. Do not proceed because prose or self-authored manifest fields sound aligned.
   Classify each reference as photographic, diagrammatic, editorial, motion-led, product-object, or mixed and pass its medium-specific difficulty checks. Measure every adaptation across composition, color, typography, media role, responsive behavior, and interaction; every set needs both a recognizably close study and a materially far study.
   Before concept validation, create or refresh a cross-run portfolio review with `continuity design portfolio-validate --manifest <portfolio-review.json>`. Review at least every four generations. Fingerprint palette, typography, composition, labels, status marks, signature language, material, and section rhythm; identify recurring tells and the strongest prior generation. Every concept must change at least three fingerprint dimensions, explicitly justify any retained tell, and the compelling current concept must visibly challenge the strongest prior output while preserving project truth.
   Record `direction_count`, its material `direction_count_basis`, and a `direction_assessment` naming material ambiguities and any resolved by inspected evidence:
   - one only when both the organizing idea and the expressive posture are settled by evidence or an explicit user choice;
   - two when one material tradeoff remains;
   - three when multiple materially different approaches remain plausible.
   Do not use document completeness, safety coverage, or a polished first idea as evidence that the organizing idea is settled. One direction is invalid while a recorded material ambiguity remains unresolved.
   Authored directions require the assessment, and the supplied direction count must equal the assessed count. One unresolved material ambiguity requires at least two directions; two or more require three. A preferred idea may be recommended, but recommendation does not erase credible alternatives.
4. Author project-specific directions from the intent, evidence, current design, audience, constraints, preservation requirements, and consequential context. Supply the directions in the private input; do not rely on the CLI's recovery fallback as completed creative work. Make directions differ in organizing idea, experience architecture, expression, and tradeoffs—not merely colors, fonts, or decoration. Give each direction a recognizable creative signature grounded in the product's purpose, and state how that signature appears in composition, type, color, form, imagery, motion, or voice as applicable. For media-led narrative work, first run the private six-to-ten narrative-spine burst in [cinematic media storytelling](references/cinematic-scroll-experiences.md), define the intended cinematic outcomes, reject film-as-decoration concepts, choose among a looping hero, chapter loops, normal playback, scroll-linked playback, and still equivalents, then collapse the strongest candidates into the normal one-to-three reviewable directions. For created or materially reshaped work, supply `creative_provenance` and `distinctive_expression`: derive subject-world cues from inspected or supplied project evidence, label creative inference honestly, take one bounded aesthetic risk, reject interchangeable defaults, define a concrete expression system, allocate an `expression_budget`, and name representative compositions and uniqueness checks. Infer and record a `design_register` of `brand`, `product`, or `mixed`; use a concrete `usage_scene` to calibrate the work; and choose a separate `color_commitment` of `restrained`, `committed`, `full-palette`, or `drenched` so expression weight does not automatically mean saturation. Record a `target_weight` and `exploration_ceiling` from `0.0` to `1.0`, whether the posture is inferred or user-supplied, and the project-specific rationale. Infer a useful posture when the user does not provide one; do not turn any of these fields into intake requirements. Use `boundary-study` to label deliberately over-normal exploration without weakening accessibility, readability, truthful state, authority, recovery, preservation, responsive integrity, or provenance. Define a `brand_signature` that turns the identity premise into a primary carrier, recurring carriers, utility, quiet, and campaign modes, subject-derived semantic tokens, a context transformation matrix, prohibited substitutions, and recognition tests. Require the signature to survive beyond one hero and generate a family of surfaces without repeating one layout. Complete an `anti_reflex_review` that rejects both the obvious category default and the fashionable counter-default when neither is supported by the subject. For implementation-facing targets, compile a stack-grounded `implementation_system` using [executable design systems](references/executable-design-systems.md): summarize available capabilities and material gaps; define semantic tokens, relational surface grammar, type, layout, motion, component recipes, responsive transformations, change-impact checks, and hardening checks. Link the expression to its provenance IDs so these decisions render into `design.md` and remain available to later planning and artifact review. Safety rules constrain the concept; they must not become the concept or bury its aesthetic point of view. Do not turn catalog taxonomy into the concept, outline, headings, or vocabulary unless the user explicitly requested it. Use inferred packs as silent creative context and review checks. Resolve tensions through [composition precedence](references/composition-precedence.json); never resolve them by prompt order or averaging. Translate the direction into its target-appropriate dimensions from [design grammar](references/design-grammar.md), content rules, audience strategy, prototype boundaries, component and pattern rules, implementation guidance, acceptance and drift checks, and prohibited patterns. Apply [prototype integrity](references/prototype-integrity.md) when a prototype, representative content, or multiple audiences are involved. Autonomy, comprehension, accessibility, refusal, correction, exit, and recovery remain non-negotiable safeguards rather than stylistic callouts.
5. Refine each authored direction through the ordered passes in [distinctive expression methodology](references/distinctive-expression-methodology.md): provenance grounding, divergent exploration, boundary push, contextual review, restraint edit, responsive transformation, and artifact critique. Infer the useful review perspectives from the project, target, consequences, and installed references; never require the user to name lenses or repeat their taxonomy in the result. A contextual review is complete only when `contextual_reviews` records why each material perspective applies, its concrete finding, the resulting design response, favorable behavior preserved, and an observable verification. Do not satisfy this with a generic statement that the design was reviewed. Record explicit routing only when the user or project evidence names the perspective; otherwise label it inferred. Before selection, complete and record the first six passes with what changed, what was deliberately preserved, and any unresolved issue. Keep artifact critique pending until representative HTML, PNG, document, image, or other target-native output exists. If artifact critique changes the approved direction, create a new revision and require exact approval rather than silently changing the contract.
   Treat natural requests to make a direction bolder, quieter, distilled, typeset, laid out, colorized, animated, delightful, hardened, or polished as bounded refinement intents—not separate skills or permission to implement. Change the smallest relevant portion of the contract, re-run every affected downstream pass, preserve recorded favorable behavior, and create a new exact revision when an approved contract changes.
6. Require at least one concept whose owned, supplied, or generated media forms the thesis, composition, and behavior rather than merely supporting copy. Classify every generated study as `concept-forming`, `supporting`, or `rejected`. Carry every shortlisted signature through opening, at least four downstream roles, quiet or edge states, responsive transformations, and a hash-bound purposeful-motion or explicit-no-motion storyboard. For presentation work, require at least four structural slide roles, one narrative peak, one quiet or rest state, separate live-presentation and read-ahead reviews, and slide-by-slide proof that every audience-facing title, body line, label, value, source, and visible qualification is present and readable. Shorten copy or change the composition before shrinking, clipping, hiding, or obscuring information. Present directions with progressive disclosure. Lead with a compact decision view: reconstructed problem, current strengths, recommended direction, creative signature, principal tradeoff, preservation promise, and material unknowns. Put detailed grammar, safeguards, implementation constraints, and drift checks in the durable contract beneath it. Clarity is not completeness removed; it is the important choice made visible before supporting detail.
7. Apply category-pack acceptance questions as review gates. When foundation and category guidance differ in specificity, use the category guidance without weakening foundation safety or accessibility constraints.
8. Apply every pack according to its `modalities` entry for the requested target:
   - `validated` means the pack contains direct evidence for that modality;
   - `inferred` means apply only its `modality_independent_principles` and label the application inferred;
   - `not-applicable` means do not apply that pack to the target.
   Report `mixed` when a target combines validated and inferred packs. An empty modality-independent list supplies no inferred guidance. `campaign` and `platform` are evidence contexts used by applicable packs, not additional publication targets or implementation authority.
9. For UI or web work, default to a `complete-prototype` completion contract unless the user explicitly asks for exploration only. Before drafting, provide an evidence-backed component map classifying each material need as `reuse`, `compose`, `extend`, `custom`, or `missing-capability`, with required states, responsive transformation, accessibility behavior, and custom expression. Provide an asset strategy for every material image, illustration, diagram, icon family, texture, media file, or deliberate omission. Existing, supplied, and derived assets require source references. For cinematic media work, bind actual media metadata, intended outcomes, playback grammar, the beat-or-loop-to-chapter matrix, media loading and error states, no-video and reduced-motion equivalents, and the commercial action before implementation. A library supplies proven behavior and semantics; it must not silently supply the product's finished aesthetic.
10. Run `continuity design draft --input <design-input.json>`. When useful, render a first-party visual-language atlas with `continuity design visual-atlas --input <request.json>`. Supply the same real project copy to every plate and make each plate change its organizing idea, typography roles, density, surface, motion intent, and responsive behavior. Do not expose the catalog taxonomy as a questionnaire or present palette swaps as contrasts.
11. Build private numbered visual evidence before selection. Decompose named references into composition, typography, density, imagery, motion, and voice; state the inferred appeal provisionally and define the project-specific transformation. Build a 12–20 tile moodboard across at least two of `subject-material`, `treatment-light`, and `graphic-spatial` when live research completes. A named web reference requires separate, legible hero, deep-section, interaction-state, and narrow captures before making claims about its grammar; a single homepage still supports only claims visible in that still. Save and hash every captured image, require source diversity, record its intended lesson and project mechanic, and later disposition every tile as adopted, transformed, rejected, or reference-only. Keep third-party evidence private and non-shipping. Render moodboards, concept comparisons, reference-transfer plates, and visual deltas with actual local images; the renderer does not create placeholder art. A reference-transfer plate must visibly place source, reconstruction, literal substitution, and controlled adaptation together at comparable crops.
12. When direction is materially unclear, create two or three equally developed selectable boards without a preselected winner. When direction is clear, author one selectable recommended direction and one or two non-selectable `contrast-study` boards that test a named uncertainty. Do not invent weak directions to satisfy a count. Every workflow-v3 board requires executable `typographic_transfer` and `composition_asset_plan` evidence. A layered relation must prove registered background, live-type, and RGBA foreground planes; a characteristic type direction must prove the computed family and rendered silhouette with real copy. Every board also requires a thesis, impact thesis, primary creative carrier, emotional register, seed lineage, system extractions, one signature move, palette, real-copy type specimen, planned typography system, planned media system, distinct composition family, a journey of at least five stages, its own mobile/tablet/desktop runtime probes, distinct rendered wide composition, distinct narrow transformation, imagery or material treatment, a motion storyboard or explicit no-motion choice, preservation promise, tradeoff, anti-reference, and comparable fidelity. A presentation board additionally requires a narrative spine, at least four visibly distinct slide silhouettes, a slide-role inventory, repeated-template ratio, concept-forming media disposition, a sequence contact sheet, and projected/read-ahead transformations. Across the concept set, require a unique typography strategy, art-direction family, and composition family per concept, plus at least two typography families. Palette or font swaps do not count as distinct concepts. If generated-image lineage contributes, extract at least three non-image system decisions so the image changes the design language instead of remaining decoration.
13. Run the creative-range gate before the slop gate: write distinct five-second reactions, compare every pair across at least three material dimensions, challenge each concept with an opposing hypothesis, verify the declared typography, media, composition, page-grammar, interaction, and page-depth counts, and verify project identity wins over recurring Continuity house tells. Each concept needs a tall full-page strip, an exact journey index, a deep link to the complete prototype, and its own `reference_adaptation_id` from the passed translation stage. The comparison surface must show readable opening, proof, interaction, quiet-or-edge, and closure crops plus one full-page overview; a postage-stamp full-page strip is navigation evidence, not sufficient visual comparison. Validate page-grammar congruence against the complete prototype: implement and mark all three required behaviors for the selected grammar family, demonstrate each across at least two journey stages, and record the strongest match plus weakest mismatch. A page that only describes its grammar does not pass. Next validate deep-journey structure. Ordinary journeys need at least four artifact-marked structural expressions across all declared stages. A `single-canvas-instrument` instead needs one marked persistent canvas and at least four artifact-marked state recompositions of that same canvas. Record the deepest signature change and the remaining repeated-pattern risk. Its signature must control at least three different journey roles, and generated-media lineage must be retained or translated into execution of comparable capability—not flattened into primitive decoration. Mark the rendered carrier with `data-continuity-signature` and one or more `data-continuity-signature-role` values across opening, proof, interaction, quiet-or-edge, and closure. Mark labels, authority boundaries, or truth claims that interaction must not rewrite with unique `data-continuity-invariant` IDs; capture default and changed states with the unmodified browser probe. Workflow-v3 validation rejects a signature absent from mobile or the initial opening viewport and rejects any protected semantic value that changes between states. Then run a separate multimodal impact review: bind wide and narrow evidence, judge identity specificity, emotional resonance, craft coherence, and reference-translation fidelity, name the weakest moment, and require at least one concept to be `compelling`. Next run `continuity design slop-check --target <concept> --manifest <slop-manifest.json>` for every direction and study, including the `translation_fidelity` context, followed by `continuity design concept-validate --manifest <concept-manifest.json>`. Answer each visual-review question with `pass`, `fail`, or evidenced `not-applicable`, plus reviewer, time, and hashed PNG regions. A failed visual answer creates a finding. Hard failures and project drift cannot be waived or marked not applicable. Bind every concept report to its exact wide and narrow renders and bind separate runtime probes to every concept; comparison-page probes cannot stand in for concept evidence. A validated concept set enters `awaiting-feedback`, not selection.
14. Gather reactions against visibly numbered elements as `keep`, `change`, `avoid`, or `uncertain`, preserving the user's natural language and why. After every material refinement, show a visual delta of what changed, what stayed, and why. Record feedback with `continuity design feedback-record <design-id> --input <feedback.json>`. Any `change` or `avoid` reaction creates a new revision and invalidates selection and affected slop evidence even if the input misclassifies the change. The next draft automatically carries the feedback rounds, accepted choices, rejected choices, and unresolved decisions forward. Continue until the user explicitly marks the refreshed concept set ready for selection; do not optimize for the fewest turns.
15. Require the user to select a ready direction or explicitly combine directions with `continuity design select`.
16. For a selected complete UI prototype or presentation document, create the ignored private package under `.continuity/private/designs/<design-id>/<revision>/`. Use the project's installed framework, configured libraries, tokens, components, and preview harness where safely available. Do not add production routes, modify application behavior, install dependencies, or include the prototype in production build inputs. Produce a coherent representative page, smallest complete workflow, or complete deck sequence with representative content, required local assets, relevant states, and desktop, tablet, and mobile captures. A hero plus generic cards or a cover plus repeated title-and-body slides is not a complete composition. For presentation work, mark every frame with `data-continuity-slide`, every data-bearing region with `data-continuity-data`, render slides individually, verify encoded format and viewport identity, run the browser probe at every required viewport, fail the stage when any copy or data is hidden, clipped, outside its frame, too small, low-contrast, or rendered before fonts load, assemble a contact sheet from those verified frames, and review live and read-ahead modes separately. For media-led prototypes, preserve supplied media unchanged, read intrinsic metadata instead of hardcoding duration, separate media control from chapter choreography, and include loading, buffering, failure, direct navigation, interruption, quiet static, reduced-motion, and no-video states. For looping hero or chapter media, also demonstrate the seam, poster transition, autoplay rejection, pause or stop, offscreen suspension, phase-independent copy, mobile focal crop, and decoder budget. Do not add scroll-scrubbing, smoothing, parallax, or an auto-tour unless project evidence justifies each one.
   Set `consequence_level` from the actual stakes. For high-consequence prototypes containing fixture content, record content provenance before generation and visibly qualify every inferred or illustrative identifier, date, amount, warning, remedy, contact path, image, or verification claim. Never label invented content or generated imagery as verified. If verified subject material is unavailable, use an explicit no-evidence state or clearly labeled illustrative placeholder that cannot be mistaken for operational truth.
17. Create a version 3 manifest from [complete-prototype-manifest.example.json](references/complete-prototype-manifest.example.json). Bind source files, captures, implementation context, component map, asset strategy, selected design hash, approval-bundle hash, approved type-transfer and composition-plan hashes, claims, decided insights, viewports, states, and validation evidence. Run `continuity design probe-prepare --target <prototype.html>` to inject stable document and source-bundle fingerprints and receive the exact runtime-source declaration, including files reached through TypeScript path aliases. Include every returned source in the manifest. Run the shipped browser probe again against the current desktop artifact and bind its unmodified output as `fidelity_runtime_probe`; its source-bundle fingerprint must match the dependency closure Continuity resolves from the current target document, and prototype and implementation validation re-run the approved type and plane contract against that rendered DOM. Run the prototype-stage slop check and bind its passed report, then run `continuity design prototype-validate --manifest <manifest.json>` before approval.
18. Complete artifact critique against the target-native renders. Run `scripts/artifact-browser-probe.js` in every required browser viewport and apply [web artifact quality](references/web-artifact-quality.md) to web output. Treat findings as evidence, not automatic aesthetic bans. Review the required viewports together as one responsive composition—prefer a side-by-side contact sheet or comparison board in addition to individual captures—and compare the artifact with the approved responsive delta matrix. Check signature recognition, persistence beyond the opening composition, quiet-mode continuity, family-generation range, subject specificity, library-default leakage, semantic structure, output purity, content authenticity, asset quality, type craft, spacing rhythm, component coherence, state coverage, responsive transformation, accessibility, and document-to-artifact drift. Run the visual and context layers of the native slop gate. Record every material finding with artifact location, severity, response, verification, and any evidence-backed intentional override. A `critical`, unresolved `error`, contract drift, or undisposed default-risk warning blocks the stage. Bind every visible factual or verification claim to content provenance and visible qualification. Resolve every planned asset with bound artifact evidence or an explicit deliberate omission. If critique changes the direction or durable contract, create a new revision, regenerate the affected artifact, and validate again. Never leave artifact critique pending when rendered artifacts exist.
19. Present the refined exact private draft, design-document hash, approved visual-reference hash, and combined approval-bundle hash. Do not promote it without exact approval.
20. After the user approves the exact authorization text printed by `design select`, run `continuity design approve`. This writes `docs/design/design.md`, eligible owned references under `docs/design/references/`, and `.continuity/design.json` schema v2.
21. Run an implementation-stage slop check and re-run `continuity design artifact-validate --manifest <manifest.json>` against the approved record. Do not call an artifact implementation-facing unless candidate, approved, and slop validation pass. The private prototype remains design evidence and never becomes production implementation automatically.

## Approval boundary

The required authorization text is printed by `design select` and must name the design ID, revision, exact document hash, and approval-bundle hash for the creative-director workflow. Approval authorizes publication of that exact document and eligible visual-reference bundle only. It does not create, approve, revise, dispatch, or execute a goal.

A later design revision creates new evidence. It never changes an existing goal automatically. When implementation is later planned, include the approved design ID in `design_ids`; `$continuity-plan` derives and hash-binds the exact design revision.
