# Retrieval and Curation

Read this reference when selecting memory for planning, promoting a note, resolving conflicting entries, or deciding whether knowledge is current enough to trust.

## Retrieval order

1. Search by domain concept and behavior, not only the user's exact words.
2. Prefer `current` entries verified against the relevant code or documentation state.
3. Follow relationships to superseding, conflicting, dependent, and roadmap records.
4. Report exact IDs, source paths, headings, confidence, verification date, and unresolved gaps.
5. Distinguish “no matching memory” from “matching memory exists but is stale or disputed.”

## Promotion rubric

Promote only when the content is:

- durable enough to matter beyond the current conversation;
- project-relevant and sanitized;
- supported by cited evidence;
- authorized by an active documentation or execution goal;
- expressible as current, proposed, disputed, superseded, or historical;
- assigned a stable ID and relationships.

Do not promote raw feedback, private identity details, temporary debugging output, unsupported interpretation, or an instruction. Preserve those in private note history.

## Conflict handling

Good: “MEM-018 states the integration uses mechanism A, but current code evidence shows mechanism B. Mark MEM-018 disputed pending verification; do not use it as settled planning evidence.”

Bad: silently edit MEM-018 or cite it because it better supports the proposed plan.

When understanding changes, create or verify the replacement, link it, and supersede the old entry. Keep historical context when it explains compatibility or prior decisions.

## Brief quality

A useful memory brief includes:

- relevant current entries and why they apply;
- positive constraints or successful behavior to preserve;
- disputed, stale, or contradictory entries;
- missing knowledge that affects decisions;
- exact citations usable in the goal record;
- confirmation that private similarity results are recommendations, not trusted evidence.

## Handoff checklist

- Exact memory IDs and citations are present.
- Freshness and verified code state are stated.
- Contradictions and unresolved gaps are visible.
- Canonical and private sources are distinguished.
- Planning receives evidence, not inferred authorization.
