# Default Project Goal Dispatch

When the portfolio supervisor returns a due `dispatch` action, start a separate task in that repository and pass its exact one-time claim token, idempotency key, and selected due goal ID to `scheduler run-start`. The start must atomically consume the claim before work. Run `project doctor`, inspect `workflow status --goal-id <goal-id>`, and apply the installed `$continuity-local` behavior with `$continuity-dispatch`. Dispatch at most one goal per project when the same-date review succeeded and the goal is queued, due, dependency-satisfied, unlocked, and preflight-compliant. During execution, send heartbeats, implement and run candidate checks, complete documentation/memory/roadmap/evidence artifacts, commit, run and record the final source-bound `$continuity-test`, push the exact tested commit to a draft PR, then apply `$continuity-merge` against the local, remote, PR-head, and PR-base bindings. End successful overnight delivery at `review-ready`; never record business completion or merge without next-business-day human review evidence. Start different projects concurrently only within the active-plus-reserved portfolio cap. Never infer approval, bypass failed gates, execute held work, auto-merge, force-push, or move private state outside its project. Record claim hash, task IDs, configuration hash, machine test report, merge assessment, workflow handoff, and local dispatch outcomes.
