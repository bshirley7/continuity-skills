# Default Project Goal Dispatch

When the portfolio supervisor returns a due `dispatch` action, start a separate task in that repository and pass its exact one-time claim token, idempotency key, and selected due goal ID to `scheduler run-start`. The start must atomically consume the claim before work. Run `project doctor` and apply the installed `$continuity-local` behavior with `$continuity-dispatch`. Dispatch at most one goal per project when the same-date review succeeded and the goal is approved, due, dependency-satisfied, unlocked, and preflight-compliant. During execution, send heartbeats, run `continuity test run` after implementation, record its source-bound machine evidence through `$continuity-test`, then apply `$continuity-merge`. End successful overnight delivery at `review-ready`; never record business completion or merge without next-business-day human review evidence. Start different projects concurrently only within the active-plus-reserved portfolio cap. Never infer approval, bypass failed gates, execute held work, auto-merge, force-push, or move private state outside its project. Record claim hash, task IDs, configuration hash, machine test report, merge assessment, and local dispatch outcomes.
