# Default Project Goal Dispatch

When the portfolio supervisor returns a due `dispatch` action, start a separate task in that repository, acquire its fast-forward-only remote lease for the selected goal, and pass the exact one-time claim token, idempotency key, and due goal ID to `scheduler run-start`. Lease conflict or remote failure is a non-launch state. The start must atomically consume the claim before work. Run `project doctor`, inspect `workflow status --goal-id <goal-id>`, and apply the installed `$continuity-local` behavior with `$continuity-dispatch`. Dispatch at most one goal per project when the same-date review succeeded and the goal is queued, due, dependency-satisfied, remotely leased, locally unlocked, and preflight-compliant. During execution, send heartbeats, implement and run candidate checks, complete documentation/memory/roadmap/evidence artifacts, commit, run and record the final source-bound `$continuity-test`, push the exact tested commit to a draft PR, wait for required hosted checks, then apply `$continuity-merge` against the local, remote, PR-head, PR-base, CI, and merge-state bindings. End successful overnight delivery at `review-ready`; never record business completion or merge without next-business-day authenticated human review evidence. Start different projects concurrently only within the active-plus-reserved portfolio cap. Never infer approval, bypass failed gates, execute held work, auto-merge, force-push, or move private state outside its project. Record claim hash, task IDs, configuration hash, lease commit, machine test report, merge assessment, workflow handoff, and local dispatch outcomes.
